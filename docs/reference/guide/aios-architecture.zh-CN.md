# AIOS 架构

> **迁移设计参考（非当前实施规范）**：本文由 [guide/engineering/aios-architecture.zh-CN.md](https://github.com/xiongweilin/guide/blob/511c073322c6b38ed2d36b32492836abf4d69b58/engineering/aios-architecture.zh-CN.md) 迁入，以保存原有工程分析。当前行为、权限、状态、契约和实现以 AIOS 现行 `docs/`、`contracts/`、源码与测试为准。概念框架以 [guide](https://github.com/xiongweilin/guide) 为准；本文不反向定义框架或现实本体。

[English](./aios-architecture.md) | [简体中文](./aios-architecture.zh-CN.md)

> 定位：把“现实—目的性有限行动者—当前边界—充分性—探索/决策—现实反馈”落到一个长期自主运行的人工智能系统中。AIOS 是应用，不是理论来源。

## 1. 从框架到运行时

AIOS 本身是一个目的性有限行动者。它不会把“现实”实现成总本体，也不会声称 personal world、数据库、模型或知识图谱已经拥有完整世界。

运行时需要保存：

- **当前边界**：区分、关系、因果、时序、可能性、价值；
- **认识状态**：来源、证据、未知、争议、版本与时效；
- **充分性依据**：为什么当前转换现在足够；
- **探索 / 决策状态**：边界不足时重开，足够时形成选择；
- **行动链**：决定、授权、执行、现实效果、观察、验证、结果、恢复与重开。

六维不对应六个服务。它们是语义要求，可以由不同领域对象共同承载。

## 2. 长期闭环

```text
┌────────────────────────────────────┐
│ AIOS：目的性有限行动者                     │
│                                    │
│ 观察 / 区分当前边界                │
│ → 充分性                           │
│ → 探索 或 决策                     │
│ → 授权 → 执行                     │
│ → 观察 → 验证 → 校正              │
└──────────────┬─────────────────────┘
               │ 有边界现实效果
               ▼
            ┌──────┐
            │ 现实 │
            └──┬───┘
               │ 权威回读 / 证据 / 未知
               └────────────────────► AIOS
```

日常运行不依赖人在场。现实反馈可以使任何当前边界重新打开。

## 3. 临时外部介入

```text
人
  │ 查询 / 请求 / 必要批准
  ▼
现有 Agent 产品
（短生命周期会话）
  │ 权威检查 / 解释 / 有边界已授权修复 / 验证
  ▼
AIOS 机器边界 ─────────────► 现实
  │
  └── 报告已验证状态，然后断开
```

外部 Agent：

- 不是 AIOS 运行时组成部分；
- 不创建或持久拥有状态、责任或权限；它只能在当前会话中行使 AIOS 明确授予的有边界权限；
- 不拥有 Personal World 的规范状态或领域自有状态；
- 会话结束不会暂停 AIOS 自主运行。

`人在场 ≠ 系统操作的必要条件`

`外部 Agent 解释 ≠ 权威状态`

`外部 Agent 修复 ≠ 已成功恢复`

`提供方校正成功 ≠ 领域结果已验证`

`领域结果已验证 ≠ 领域已经恢复`

`领域已经恢复 ≠ 责任已经解除`

提供方层面的校正只能建立执行事实。领域恢复还需要由领域自身完成现实侧观察、结果资格判断以及所需验证。

API / CLI 是机器集成和维护边界，不是主要人机管理界面。

## 4. 架构区域

```text
┌────────────────────────────────────────────────────────────────┐
│ AIOS — 长期自主目的性有限行动者                                       │
│                                                                │
│ personal-world ──用途受限上下文──► 内部 Agent / 执行器        │
│      ▲                                  │                      │
│      │ 溯源 / 修订                      ▼                      │
│      └──────────────────────────────► 领域准入                 │
│                                         │                      │
│ semantic-language / world-runtime / domain controllers         │
│ 边界 / 充分性 / 责任 / 权限 / 行动链 / 恢复                   │
└─────────────────────────┬──────────────────────────────────────┘
                          │
                          ▼
                         现实
      外部系统 / 源码 / 构建 / 部署 / 流量 / 基础设施 / 组织系统

带外，仅需要时：
人 ⇄ 短生命周期 Agent 产品 ⇄ AIOS 机器边界
```

容器是部署边界，不是持久语义归属方。内部 Agent、执行器、模型提供方、监控系统和外部客户端都应保持可替换。

## 6. semantic-language：已提升的跨领域角色词汇

semantic-language 应保持小而稳定。它直接拥有的只是那些已经提升为 universal role、且错误合并会造成具体跨领域 correctness failure 的角色区分。下面更广泛的不可替代关系是 AIOS 整体的工程不变量；尚未提升的区分继续由实际相关的子系统或领域契约本地拥有并保持。

AIOS 在实质相关时应保持：

```text
现实 != 当前表示
可区分范围 != 已区分范围
默认区分 != 充分区分
关系 != 因果
可能 != 可达 != 可控 != 可调用
问题候选 != 已充分问题
解释型充分性 != 规定型充分性
规定规则满足 != 规则适用 / 当前 / 权威
证据 != 信念
观察 != 主张
主张 != 当前充分状态
意图候选 != 已确认意图
人工批准动作 != 决定
决定 != 授权
身份认证 != 表示
表示 != 状态转换权限
个人情境 != 执行权限
现实效果 != 结果
提供方成功 != 已验证现实
投影 != 权威状态
历史有效 != 当前充分
解释 != 现实
```

一个稳定语义区分不自动要求统一载荷、独立持久对象、表或服务。

对于长期自主改进，还要额外保持几类容易混淆的区别：历史记录或证据数量增加，不等于能力增强；产生新版本，不等于版本变得更强；内部评分上升，不等于外部目标真的改善；外部目标改善，也不等于系统获得了新的能力。

## 7. personal-world：个人连续性

personal-world 持有一个人的持久、持续演化、带来源，并通过 owner-local qualification / admission 实现框架充分性要求的个人情境。这个名称不表示它包含这个人的全部可区分世界；个人记录缺失也不能自动解释为现实中的缺失。

```text
来源
→ 观察
→ 主张
→ 资格判断 / 准入
→ 个人记录修订
→ 当前沿革头
→ 用途受限上下文投影
→ Agent / 已授权使用者
```

公开个人记录类型可以包括：

```text
个人事实
偏好
关系
资源链接
```

personal-world 不拥有：

```text
决定
授权
责任
运行
现实效果
领域结果
提供方执行
领域生命周期
模型私有记忆
```

模型推断不会自动成为当前已取得资格的 Personal World 状态。领域投影不会转移领域归属；上下文投影也不是新的权威个人状态。

## 8. 认知执行

认知执行是可替换边界：

```text
领域触发 / 已授权请求
+ 用途受限个人上下文
+ 领域状态
+ 运行时约束
→ Agent / 执行器
→ 边界复核
→ 必要时探索
→ 问题 / 任务充分性
→ 分析 / 提案 / 实现候选 / 测试 / 复核
```

执行器输出仍然只是候选、证据、解释、提案、实现或复核结果。生成一个新框定不会自动获得领域准入。

模型选择和路由只是传输 / 配置事项，不能扩大权限、现实效果范围或持久所有权。

## 9. world-runtime：自主连续性

world-runtime 位于已经充分的工作触发条件与领域实现之间：

```text
已充分工作触发 / 已授权请求
        ↓
受治理的自主行动能力
        ↓
world-runtime
        ↓
有边界领域实现
        ↓
现实
```

world-runtime 可以拥有：

```text
身份
认识依据引用
责任
决定 + 依据引用
Mandate / Authorization
QualificationBinding / ReviewCase
工作 / 运行
执行身份
提供方尝试身份
校正
恢复
历史沿革
```

它不拥有个人偏好、界面会话状态、软件发布语义、行政完成语义或提供方特定业务语义。

领域控制器决定领域完成和结果的具体含义。

## 10. 权限路径

```text
已认证行动者
→ 表示
→ 意图 / 提案
→ 决定
+ 当前 Mandate
→ Authorization
→ 运行时状态转换权限
→ 现实效果授权
→ 持久现实效果身份
→ 提供方调度
→ 现实
```

前一阶段不能替代后一阶段。

知道资源不产生权限；代表某主体不自动取得转换权限；取得转换权限不自动取得所有现实效果权限；执行权限不能证明领域结果。

## 11. 证据与反馈路径

```text
现实
→ 观察
→ 证据
→ 领域解释 / 结果资格判断
→ DomainReport + Outcome 引用 / 未知
→ 运行时复核 / Responsibility 评估
→ 当前自主状态
```

证据必须可追溯。World Runtime 可以记录或引用领域自有结果，但不重新解释其领域含义。当前资格变化不会改写历史证据；关键依据变化应触发复核或重新验证。

当前资格还要沿依赖关系判断：如果一个结论依赖的前提已经失效，结论不能因为历史记录仍然存在就继续被当作当前有效；与这条失效链无关、仍有独立现实依据的证据可以继续使用。评估器、规则或模型版本变化时，也必须说明旧判断为什么仍能迁移到新版本，而不能只因为新版本能读取旧记录就默认继承。

## 12. control-plane

```text
监控信号
→ 已认证入口
→ 运行时责任 + 领域分配
→ 有边界诊断
→ 修复方案充分性
→ 领域工作 / 运行
→ 运行提供方
→ 现实观察
→ 修复验证
→ 领域报告
→ 运行时责任评估 / 解除
```

诊断不是权限。提供方成功不是目标恢复。运行完成需要领域证据。

## 13. administrative-orchestrator

```text
组织请求 / 证据
→ 行政事项 / 事实 / 规则 / 义务
→ 治理依据
→ 行政执行授权
→ 运行时责任 / 工作 / 权限
→ 外部行政系统
→ 独立回读
→ 已确认结果
→ 完成评估
→ 运行时责任评估
```

规则或批准满足不是运行时授权；行政效果记录不是外部现实；事项完成不自动等于责任解除。

## 14. autonomous-development

```text
已充分开发目标 / 已准入请求
→ 开发请求
→ personal-world 上下文投影
→ 需求分析
→ 变更提案
→ 隔离实现
→ 确定性验证 + 独立复核
→ 不可变构建
→ 候选部署
→ 离线评估
→ 金丝雀
→ 晋级或回滚
→ 晋级后观察
→ 发布版本
```

autonomous-development 持有：

```text
开发目标
产品目标修订
开发请求
需求分析
变更提案
工作树 / 来源语义
验证门槛
构建制品身份
部署状态
流量暴露
反馈归因
金丝雀生命周期
晋级
回滚
发布版本
```

`Git commit ≠ 发布版本`

`测试通过 ≠ 晋级权限`

`部署健康 ≠ 产品改善`

`金丝雀完成 ≠ 发布最终确认`

### 自主开发垂直切片

```text
自主开发触发 / 已准入请求
→ 请求准入
→ personal-world 用途受限上下文 @ 修订
→ 需求分析 / 变更提案
→ autonomous-development 生命周期
→ world-runtime 受治理现实效果
→ Git / 构建 / 部署 / 流量
→ 现实
→ 测试 / 遥测 / 部署回读 / 发布证据
→ 领域结果 / 发布版本 / 回滚 / 未知
→ world-runtime 责任评估 / 校正
→ 下一自主循环
```

配置的工程执行器执行有边界的实现工作；autonomous-development 保留专业生命周期和发布权限，world-runtime 保留通用责任、授权、持久现实效果身份和效果准入。

个人世界依据必须绑定修订。个人上下文变化不会改写历史分析，但可以使旧分析失去当前充分性。

自主开发还必须区分“系统产生了更多变化”和“系统确实进步”。提交次数、版本数量、候选归档增长、测试分数、内部评估分数和前沿替换，都只能证明各自对应的事实，不能单独证明产品目标改善或能力出现了新的增长。涉及晋级时，应尽量回到固定的外部目标、现实侧读回和领域结果来判断。

如果开发流程允许检查器、评估器或晋级规则修改自己的后继版本，那么当前版本认可后继版本，不足以证明后继版本仍然可靠。至少应有一个不依赖该循环的可信起点，或者保存可以独立检查的保持依据，说明关键判断、目标和约束在迁移后仍然成立。

## 15. 现实回流

每条有后果路径都要有返回路径：

```text
现实
→ 观察 / 提供方回执 / 外部状态
→ 领域证据
→ 领域自有 Outcome 引用 / 未知 + 效果状态
→ DomainReport
→ world-runtime 校正 / Responsibility 评估
→ 当前自主状态 / 下一循环
```

只有异常需要人关注时，才通过短生命周期 Agent 投影给用户。

提供方确认不能终止闭环；传输歧义必须保留未知；只要领域支持，应独立回读现实。

## 16. 三种持久连续性

```text
个人连续性 = personal-world
自主连续性 = world-runtime
领域连续性 = domain controller
```

semantic-language 保存三者之间的角色区分。

外部 Agent 投影不是第四个持久权限存储。

替换内部 Agent / 执行器不应替换任何持久连续性；断开外部客户端也不应停止 AIOS；领域控制器可以演化而不把专业生命周期搬进 world-runtime；world-runtime 可以重启而不丢失持久自主状态。

## 17. 放置规则

只有当至少三个实质不同领域需要同一个稳定跨领域 role distinction，而且合并会造成具体 correctness failure 时，才提升到 semantic-language。提升只加入角色区分，不加入领域 payload 或生命周期。

新的持久跨领域自主行动不变量进入 world-runtime。

个人事实、偏好、关系、资源引用与上下文沿革进入 personal-world。

专业生命周期进入领域控制器。

提供方特定实现留在拥有它的领域。

Agent / 执行器与模型路由保持可替换，默认不成为持久状态归属方。

## 18. 扩展拓扑

新增执行器：

```text
自主工作 / 领域请求
→ 执行器选择
  ├─ Agent adapter
  ├─ engineering executor
  └─ specialized executor
```

新增领域：

```text
world-runtime
  ├─ control-plane
  ├─ administrative-orchestrator
  ├─ autonomous-development
  └─ future domains
```

新增提供方：

```text
domain controller
  ├─ API
  ├─ app
  ├─ device
  ├─ infrastructure
  ├─ human
  └─ robot
```

新能力不自动要求新运行时语义；更强模型不产生新持久权限；新领域也不意味着需要通用领域本体。

## 19. 稳定架构

```text
guide
  现实 / 目的性有限行动者
  六维边界
  充分性
  探索 / 决策
  行动链
       │
       ▼
aios/semantic-language
  已提升的跨领域角色词汇

AIOS
  personal-world ──► internal Agent / executor
         ▲                     │
         │                     ▼
         └────────────── domain admission
                               │
                               ▼
                         world-runtime
                               │
             ┌─────────────────┼──────────────────┐
             ▼                 ▼                  ▼
        control-plane   administrative      autonomous-
                         orchestrator        development
             │                 │                  │
             └─────────────────┼──────────────────┘
                               ▼
                              现实
                               │
          evidence / readback / result / unknown
                               └──────────────► AIOS

带外：
人 → 短生命周期 Agent → AIOS 机器边界
     检查 / 解释 / 已授权修复 / 验证 / 报告 / 断开
```

AIOS 的稳定性来自持久语义归属、现实回流和行动链，而不是依赖某个具体 Agent、模型提供方、路由器或交互客户端。
