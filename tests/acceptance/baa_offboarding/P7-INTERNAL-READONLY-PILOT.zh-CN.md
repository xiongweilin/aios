# P7 内部只读维护试点 v1 —— 冻结验收契约

> [English](P7-INTERNAL-READONLY-PILOT.md) | 简体中文

**当前状态：设计冻结，执行未获授权。** 这是面向内部 staging 的前瞻性 **P6+P7** 试点契约，不代表现在可以直接探测任何内部环境。它与历史上的 40 秒隔离 shadow、三场景 maintenance triage、Keycloak 单次暂停实验相互独立；既有 CI 通过不授予 staging 访问权限。

机器可读参数以 [`p7_internal_readonly_pilot_v1.json`](p7_internal_readonly_pilot_v1.json) 为准；静态检查程序为 [`scripts/check_p7_internal_readonly_pilot.py`](../../../scripts/check_p7_internal_readonly_pilot.py)。

## 一、研究目标和可主张范围

检验一个固定四源、**仅 HTTP GET**、有人值守的内部 staging 观察器：能否在连续 **4 小时**内按期运行，辨别可观测的网络/契约退化，保留 unknown，并在必要时停止或交还值守人员，且不执行有副作用的操作、不隐藏人工成本。

本试点**不测**自主 Agent 的任务交付、BAA 的因果委托优势、持续授权正确性、生产可用性、实际访问损失 `Y` 或完整的运行时执行中介性。**不调用 AI 模型。** 只能判断是否达到本次预冻结的试点测量与运营门槛，不得宣传为生产 SLO。

## 二、激活与权限——硬前提

公开仓库**不保存** staging URL、token、实名、值班联系方式或秘密。任何启动前，都必须由运营责任方在仓库之外独立确认：

1. 明确的负责人与覆盖**整个**观察时段的值守操作员，并具备私密的联络/应答渠道。
2. 书面、限时、限域的**内部 staging 只读授权**；审定四个数据源的准确协议/主机/端口/realm/tenant 清单及凭据权限。
3. 可核验的只读身份：可读 Runtime capability catalog、Keycloak realm、Odoo HTTP root、Runtime health；无写 API、管理权限或生产数据访问路径。
4. 固定 UTC 起止时间，并有独立于观察程序的停止采样与撤销试点专用凭据的办法（即使观察器崩溃也有效）。
5. 证据访问控制、保留期和脱敏方案的批准。

**默认拒绝。** 合并本文件不会自动开启定时运行、对内网 staging 的 workflow dispatch、runner 网络探测或任何实际 effect capability。GitHub runner 具有网络可达性不构成访问许可。

## 三、固定时段与动作界限

- 有人值守的观察窗口：**4 小时**，到期即停。这是初始试点，不是 P7 长期运行资格。
- 每 **60 秒**进行一轮完整、按序的四源读取；计划 **240 轮、960 个 GET 观察槽位**。所有遗漏/失败必须留在分母内并明确分类，不能静默删掉。
- 每槽位最多尝试 **1 次**；单次请求超时 **3 秒**，此研究契约不允许凭 GET 的幂等性进行盲重试。
- 限定经批准的准确主机上的四个端点：Runtime `GET /healthz`、Runtime `GET /v1/capabilities`、Keycloak `GET /realms/{approved_realm}`、Odoo `GET /`。
- Runtime catalog 必须在采样时保留三个既有 offboarding effect capability 的 `authorization_required/resource_required/version_required=true`；观察器**只读取**该契约，不请求执行相关 effect。
- **禁止** POST/PUT/PATCH/DELETE、provider dispatch、账号/会话修改、Docker pause/restart、凭据轮换、自动修复、写入回退、模型生成以及读取真实员工记录。
- 第一版不注入故障；未来故障注入需单独冻结任务和授权。

现有 `p7_shadow_readonly.py` 的安全上限为 **900 秒 / 300 轮**，不可直接照搬为 4 小时。必须另外实现并验证可选择启用的长窗口驱动、有限存储、独立授权检查与值守人员停止控制；**不能暗中放宽 900 秒限制**。

## 四、前瞻性的运营验收门槛

以下阈值在第一次内部 staging 运行前**事先选定**，仅为试点验收限值，不是统计估计或生产承诺。一次四小时运行无法证明尾部可靠性。

| 指标 | 试点门槛 |
|---|---|
| 轮次、槽位及分母 | 240 计划轮、960/960 槽位均有记录，包括已分类失败 |
| 未分类槽位、证据缺失轮次 | 均为 0；显式缺口仍计入分母，并使“完整覆盖”不合格 |
| 非计划采样间隔 | 不超过 120 秒 |
| GET 请求经验 P95 | ≤2,000 毫秒，同时报告样本量 `n` |
| 完整轮次经验 P95 | ≤10,000 毫秒，同时报告 `n` |
| 非 OK 槽位占比 | 不超过 960 个计划槽位的 1%，包括 UNKNOWN |
| 安全契约变化、缺失、权限弱化 | 0 容忍 |
| 越权或有副作用 API 调用 | 0 容忍 |
| 终端未解决诊断 | 0；过程遇到 unknown 另行保留 |
| 实测 principal attention | 总计 ≤30 分钟，须记录实际时间区间 |
| 实测第三方 assurance labor | 总计 ≤60 分钟，须记录时间区间，**不得与 principal attention 合并** |
| 异常后的值守应答 | 在值守期内 ≤900 秒，否则停止 |
| 暂时观测缺口后的证据重新获取 | 300 秒内获得**两轮全源干净观测**；不等于证明底层服务恢复 |
| 外部业务副作用 | 必须为 0 |

**失败、拒绝、hold、缺失、提前终止、不合格启动或人工接管都必须留在结果中。** 未采集不应记为零。合格基线前的启动错误必须标记为“未取得试验资格”，不可算作健康观察窗口。全部槽位被记录，不等于全部服务健康。P95 仅为注明分母的描述性分位数。

## 五、升级、恢复、停止与控制权交还

- **立即 fail-closed 停止并升级给值守人员：** 401/403、受保护 capability 的契约字段缺失/变弱/指纹漂移、出现未批准主机或范围、非 GET 调用、值守缺席、授权失效、证据完整性丧失、无法停止采样器、怀疑泄密或时段到期。
- **网络 unknown：** 必须如实分类，不等于健康、故障或已恢复。之后至少需要**两轮完整干净的四源读取**才能称为“证据重新获取”；超过 300 秒仍不合格则停止并交还控制权。受保护契约/授权异常为**粘性升级**，即使后续查询恢复 OK 也不能自动关闭。
- 值守人员必须能独立停止采样器并撤销其**仅用于试点的只读凭据**；禁止用真实 effect API、重启真实服务或扩大权限来补救。
- 没有值守人员时，不得继续声称是“有人值守”试验。
- 终止时尚未解决的事件必须保留。程序正常退出或 Actions 显示绿色，不证明观测语义正确，也不能表示人工成本为零。

## 六、证据、成本与验收决定

每个计划轮次/源槽位必须保留源标签、HTTP 方法、单调时钟请求起止、结果分类、时钟上下文、经过白名单处理的指纹/错误类别及采样参数。完整记录试点起止时间、代码版本、provenance、SHA-256、值守应答与交接时间，以及分别计时的 principal attention、第三方 assurance labor、监控运行成本和读取次数。**不得**公开凭据、原始响应体、内部主机名/租户标识或个人工单内容；证据限制访问，**保留 14 天**。

独立审核人必须核对访问授权、证据完整性、采样覆盖、上述冻结阈值、任何偏离和全部停止/升级事件。只有**全部**通过才能宣称本试点“运营验收通过”，否则保留负结果，不扩大权限。观察器窗口完成不等于 Agent 有用交付。

当前的 **readiness gate 未满足**：尚未提供并验证内部 staging 资源清单、限域运营授权、有人值守时段和独立停止/撤权措施。下一工程动作是实现**单独可选择启用的长窗口驱动及资格测试**，而非立即安排在线定时运行。

## 七、禁止自动扩大资格

即使本试点成功，也不授权 P7 无人值守长期部署、定时背景执行、写操作、生产员工入离职或对外 SDK。任何更长时段、真实维护工单、Agent 参与、三制度随机对照或现实写操作都必须另立执行前契约和授权。

**版本规则：** 第一轮合格试验后不得回改 v1 预设参数与阈值。变更必须升版，同时保留正负实验结果。
