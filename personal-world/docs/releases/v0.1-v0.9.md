# v0.1-v0.9 evolution

This repository was built as a cumulative v0.9 freeze candidate. The semantic milestones remain
separately documented so future changes can be judged against the responsibility introduced at each step.

## v0.1 — Provenance Spine

Introduced SourceDescriptor, Observation, Claim, immutable provenance references, strict public models,
SQLite durability, and stable IDs.

Exit invariant: no durable personal fact can exist without a source reference.

## v0.2 — Qualified Personal Facts

Introduced PersonalFact, record lineage, revision CAS, candidate/current/contested/revalidation states,
and explicit admission.

Exit invariant: Claim != current PersonalFact.

## v0.3 — Relationships & Resource Links

Introduced Relationship and ResourceLink without importing domain lifecycle semantics or secrets.

Exit invariant: Personal World can identify relationships to external reality without owning that reality.

## v0.4 — Preferences

Introduced explicit, imported, accepted-inference, and unaccepted-inference preference origins.

Exit invariant: model inference cannot silently become an accepted preference.

## v0.5 — Temporal Continuity

Introduced observed time, record time, validity intervals, history, and as-of reads.

Exit invariant: historical state can be reconstructed without rewriting old revisions.

## v0.6 — Context Projection

Introduced purpose-limited ContextProjection and minimum-necessary filtering.

Exit invariant: cognitive consumers do not need unrestricted canonical state.

## v0.7 — Privacy & Service Trust

Introduced authenticated service identity, purpose profiles, sensitivity ceilings, audit-ready provenance,
redaction, and erasure semantics.

Exit invariant: identity authentication and data-disclosure policy are distinct from Runtime authority.

## v0.8 — Retrieval & Cognitive Interface

Introduced structured search, derived lexical/hashed-vector retrieval, and ModelContextBundle.

Exit invariant: retrieval infrastructure can be deleted and rebuilt without losing canonical truth.

## v0.9 — Domain Integration & Freeze Candidate

Introduced DomainPersonalProjection, PostgreSQL shared-store support, multi-instance CAS, portable
PersonalWorldBundle, contract manifest, migrations, CI, security checks, and cross-surface documentation.

Exit invariant: model, agent, console, and domain integrations can change without changing the ownership
of canonical personal context.

## v1.0 gate

v1.0 should not be a feature expansion. Promotion requires multi-domain pressure, contract stability,
migration/restore validation, privacy review, and evidence that no new requirement needs to collapse the
Personal World / World Runtime / Domain ownership boundaries.


## v0.9 acceptance hardening

The 0.9 semantic surface remains unchanged while its evidence base is strengthened:

- 32 concurrent PostgreSQL writers contend on one lineage and exactly one revision may win;
- Hypothesis property tests exercise record-time and valid-time interaction, including late-arriving
  backdated corrections;
- revalidation/retraction is required to receive a fresh record-time so later qualification changes
  cannot rewrite earlier as-of views;
- erasure is checked across search, projection, history and bundle export;
- logical bundle restore destroys and recreates the store before import;
- CI performs a physical PostgreSQL `pg_dump` / `pg_restore` drill;
- `personal-world-conformance-v1` is frozen separately from the provider contract and executed over
  the real HTTP boundary.

No fifth public record kind is introduced by this hardening work.
