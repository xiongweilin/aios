# Personal World 1.0 acceptance

Status: **accepted v1.0 baseline**.

Package: `1.0.0`

Provider contract remains:

```text
personal-world-contracts-v1
```

Consumer conformance remains:

```text
personal-world-conformance-v1
```

Semantic language remains exactly `0.2.0`.

## Frozen semantics

The universal record kinds remain exactly:

- fact
- preference
- relationship
- resource-link

v1.0 does not add Goal, Decision, Authorization, Responsibility, Effect, Outcome, domain lifecycle,
agent routing, model routing, secrets, or model-private memory.

## v1.0 closure evidence

The 0.9 evidence remains required: provenance, append-only lineage, revision CAS, PostgreSQL
contention, bitemporal reconstruction, multiple DomainPersonalProjection consumers, purpose-limited
projection, cross-surface erasure, logical restore, and physical PostgreSQL restore.

v1.0 additionally requires:

1. a production instance is bound to one configured root subject;
2. cross-subject reads/writes/domain ingress/erasure/bundle surfaces fail closed;
3. production authentication uses a short-lived signed workload assertion rather than a long-lived
   bearer token;
4. a physical backup taken before erasure may be restored only in isolation, after which every
   post-backup erasure obligation is replayed before exposure;
5. the public contract names and four record kinds remain unchanged.

## Freeze rule

After 1.0, core changes require evidence of a genuinely new cross-domain durable personal-context
invariant. Domain-specific concepts remain in their Domain Controllers.
