## Acceptance conclusions

The v0.9 acceptance pressure produced two substantive semantic corrections without expanding the
universal object model:

1. revalidation/retraction must receive a fresh `recorded_at`, otherwise later qualification
   changes contaminate earlier as-of reconstruction;
2. DomainPersonalProjection must preserve one of the existing four record shapes rather than flatten
   every domain claim into `PersonalFact`.

The pressure did **not** produce evidence that a fifth public record kind is required.

The remaining production-authentication improvement—moving from long-lived service bearer
credentials toward short-lived signed workload identity or mTLS—is a deployment-security evolution,
not a reason to expand the Personal World semantic model.

## Freeze rule after acceptance

A new Personal World feature is admitted only if it represents a genuinely new durable
personal-context invariant that survives pressure from multiple distinct domains.

The following remain outside Personal World:

- Runtime Decision / Authorization / Responsibility / Work / Run / Effect / Outcome;
- domain lifecycle and professional completion semantics;
- provider execution;
- agent routing;
- LLM routing;
- secrets and credentials;
- model-private or invocation-private memory.

With these acceptance gates complete, `0.9.0` is closed as the evidence-backed pre-1.0 baseline.
The next semantic version should be `1.0` only when the project intentionally promotes this accepted
baseline; no `0.10 / 0.11 / 0.12` feature sequence is implied.
